## Android Runtime 修复: audio_service FlutterEngine 配置

- **PlatformException**: `audio_service` 插件在 Android 端要求 `MainActivity` 通过 `provideFlutterEngine()` 向后台音频服务提供 `FlutterEngine`
- **第一次尝试**: `MainActivity.kt` 重写 `provideFlutterEngine`，调用 `AudioServicePlugin.getFlutterEngine(context)` → **仍然异常**
- **根因分析**: `provideFlutterEngine` 只在"完全自定义 Activity"场景生效。`audio_service` 官方文档推荐直接继承专用 Activity 类
- **最终修复**:
  1. `MainActivity.kt`: `FlutterActivity()` → `AudioServiceFragmentActivity()`（不含 provideFlutterEngine 覆盖）
  2. `AndroidManifest.xml`: 添加 `FOREGROUND_SERVICE_MEDIA_PLAYBACK` 权限（Android 14+ 必需）
  3. `main.dart`: 移除 `await storageService.init()` 提前调用。DB 改用懒初始化（`DatabaseHelper` 首次读写时自动打开），此时 FlutterEngine 已就绪
- **关键提醒**: `MainActivity` 的类变更需要 `flutter clean` + 重新构建才能生效（Android 构建缓存问题）

- **第二次异常**: `Unable to bind to AudioService. Please ensure you have declared a <service> element` — `audio_service` 的 manifest 合并未生效
- **修复**: AndroidManifest.xml 手动添加 `<service>` (AudioService + mediaPlayback) 和 `<receiver>` (MediaButtonReceiver)，并添加 `xmlns:tools` 命名空间

## 设置页面卡死修复（第一轮）

- **根因**: `SourceNotifier`、`FavoritesNotifier`、`PlaylistNotifier` 的 `_init()` 在构造函数中 fire-and-forget 调用，但没有 try-catch。如果数据库打开失败（`sqflite`→`path_provider` 平台通道异常），未捕获异常会炸掉整个 Flutter zone，导致 UI 假死
- **修复**: 三个 Provider 的 `_init()` 均添加 try-catch，异常时静默降级（空列表/空状态），`print()` 记录错误日志

## 设置页面卡死修复（第二轮 — 根因：GPU 级联模糊过载）

- **症状**: 点击设置按钮后 APP 卡死、滑动掉帧严重（尤其在音乐播放时）
- **根因分析**:
  1. **SettingsScreen 缺少 Scaffold 背景**：`BackdropFilter` 直接模糊下方 MainScaffold 的 17 个 BackdropFilter 层 → 级联 25 层 GPU 模糊计算
  2. **positionStream 触发重建循环**：`ref.watch(playerProvider)` 监听整个 PlayerState，position 每 200ms 变更 → LiquidBottomBar + LibraryScreen 完整重建 → 重新合成 Overlay 栈 → 再次触发 25 层模糊
  3. **_SlideRightTransition secondaryAnimation 未处理**：退出页在转场期间完全可见，进入页的 BackdropFilter 模糊完整复杂背景（300ms ≈ 18 帧 × 25 次模糊 = 450 次 GPU 操作）
- **修复**:
  1. **SettingsScreen** 包裹 `Scaffold(backgroundColor: AppColors.backgroundDark)` → BackdropFilter 只模糊纯色背景而非下方复杂页面
  2. **_SlideRightTransition** 用 `secondaryAnimation` 驱动 FadeTransition（0→1 淡入覆盖）→ 转场时进入页从不透明渐变为完全覆盖，GPU 压力大幅降低
  3. **LiquidBottomBar** `ref.watch(playerProvider)` → `ref.watch(playerProvider.select((s) => (song: s.currentSong, isPlaying: s.isPlaying)))` → position 变更不再触发重建
  4. **LibraryScreen._buildHorizontalSongList** `ref.watch(playerProvider)` → `ref.watch(playerProvider.select((s) => s.currentSong))` → 同上

## 转场黑屏修复（secondaryAnimation 回退）

- **症状**: 进入设置/歌单等子页面后全黑屏
- **根因**: `_SlideRightTransition` 改用 `secondaryAnimation` 驱动 FadeTransition。MainScaffold 使用 `NoTransitionPage`（transitionDuration: 0），导致 `secondaryAnimation` 可能不推进到 1.0 → 进入页 opacity 始终为 0 → 黑屏
- **修复**: 回退到 `animation` 驱动 FadeTransition（Slide 0.1→0 + Fade 0→1）。Scaffold 背景 + select 优化足以解决 GPU 过载，不需要动转场动画

- **根因**: `liquid_glass_widgets` ^0.19.6 的 `AdaptiveGlass` 在 Flutter 3.41+ 下渲染不稳定：首帧 BackdropFilter 捕获不到背景导致模糊；路由过渡动画时 native 层崩溃
- **修复**:
  1. 移除 `liquid_glass_widgets` 依赖（pubspec.yaml）
  2. 重写 `glass_panel.dart`：用 Flutter 内置 `BackdropFilter` + `ImageFilter.blur` + `ClipRRect` 实现同等液态玻璃效果，零第三方依赖
- 效果：`blur`/`borderRadius`/`tintColor`/`showBorder` 等所有参数完全兼容，无需修改任何调用方代码

## Android 构建失败修复 — Gradle 无法下载 Flutter Engine JAR (18:09)

- **症状**: `compileDebugKotlin` → Connection reset 下载 `armeabi_v7a_debug.jar` / `arm64_v8a_debug.jar` 失败
- **根因**: Flutter Gradle Plugin (`FlutterPlugin.kt`) 默认从 `https://storage.googleapis.com/download.flutter.io` 下载引擎 JAR，国内网络无法访问 Google Cloud Storage
- **修复**: 设置环境变量 `FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`（Flutter 官方国内镜像）
  - 永久设置: `setx FLUTTER_STORAGE_BASE_URL "https://storage.flutter-io.cn"` (用户级)
  - Flutter Plugin 代码: `System.getenv("FLUTTER_STORAGE_BASE_URL") ?: "https://storage.googleapis.com"` — 读取环境变量决定 Maven repo base URL
- 构建验证: `flutter clean` → `flutter build apk --debug` 成功，APK 生成于 `build/app/outputs/flutter-apk/app-debug.apk`

## LX Music 源搜索为空 — 完整调试链 (18:09)

### 问题1: JS 源搜索返回空
- **根因**: `String.prototype.search` 导致 `typeof MUSIC_SOURCE === 'object'` 误判。MUSIC_SOURCE 是字符串（"kg"），但因为 JS 原型链问题，`MUSIC_SOURCE.search` 返回了 String.prototype.search 函数
- **修复**: `source_engine.dart` 的 `search()`/`getMusicUrl()`/`getLyric()` 添加明确 `typeof MUSIC_SOURCE === 'object' && MUSIC_SOURCE !== null` 检查 + 全局函数名检测（search/searchSong/searchMusic/handleSearchMusic/handleSearch 等）

### 问题2: 引擎初始化后 dispose
- **根因**: `source_provider.dart` 的 `_importScript()` 在验证后调用 `engine.dispose()`，然后 `getEngine()` 创建未初始化的新引擎
- **修复**: 
  - `_importScript()` 保留引擎引用不 dispose，缓存到 `_engines`
  - `getEngine()` 从 `SourceEngine?` 改为 `Future<SourceEngine?>`，确保 init() 后再返回
  - `SourceApi` 构造函数 → `static Future<SourceApi> create()` async 工厂
  - `search_provider.dart`/`player_provider.dart` 同步更新为 `await SourceApi.create()`

### 问题3: LX Music API 服务器 404
- **根因**: `88.lxmusic.xn--fiqs8s` 服务器仅根路径 `/` 返回 `{"code":0}`，所有功能端点（/search, /song/search, /url, /lyric, /api/search）均 404
- **验证**: Python 脚本测试 10+ 种 URL 格式，全部 404

### 问题4（最终解决方案）: 酷狗直接 API 回退
- **新建 `lib/services/platform_api.dart`**: 直接对接酷狗移动 API
  - `searchKugou()`: `mobilecdn.kugou.com/api/v3/search/song` — 搜索歌曲
  - `getKugouUrl()`: `m.kugou.com/app/i/getSongInfo.php` — 获取播放链接
  - `getKugouLyricRaw()`: `m.kugou.com/app/i/krc.php` — 获取 LRC 歌词
  - 歌曲 ID 格式: `kg_{32-hex-hash}`
  - 静态方法: `isKugouHash()` / `extractHash()`
- **source_engine.dart 修改**: search()/getMusicUrl()/getLyric() 在 JS 引擎和 API 服务器都失败后，回退到酷狗直接 API
- 验证: 三个 API 端点均已用 Python 测试通过，返回有效 JSON/LRC 数据
- **最新 APK**: `build/app/outputs/flutter-apk/app-debug.apk`（已成功构建）
